测试集：
- 5 道大师题
- 5 道极限题
- 来源：用户提供的 sudoku.vc 截图

图片识别：
- 10/10 题盘成功切分为 81 格
- 810/810 格“主数字 / 空格”判断正确
- 对每张截图做原图 + 4 次轻微四角偏移，共 50 次识别回归：50/50 题面完全一致
- 小号界面数字不会进入棋盘；图片导入后继续做行/列/宫冲突与可解性检查

解题引擎：
- 10/10 从初始题面连续执行到完整解
- 总计 627 个逻辑步骤
- 每一步执行后均检查：无重复、无零候选空格、当前盘面仍可解

- 同时保留 X-Wing、Swordfish、Jellyfish、XYZ-Wing、Skyscraper、2-String Kite 检测；若极难盘面仍无模式可推进，会用“矛盾链”作可验证排除

状态与交互：
- 高阶候选删除改为持久保存，不再下一步自动恢复

- 手工修改/擦除数字时会清空旧的逻辑删除，避免产生过期候选状态
- “提示1 / 提示2 / 完整逻辑 / 执行这一步”已接入同一逻辑步骤

- PWA 缓存版本已更新为 v4，降低旧版本缓存干扰

注意：
- sudoku.vc 当前字体会优先使用离线模板识别；其他字体或照片会自动回退到 Tesseract.js，因此首次使用回退 OCR 时需要联网。
- 手机实机仍建议先部署到 test/ 路径验证 Safari/PWA 触控体验，再替换正式版。

## v4.1 实机修复
实机反馈暴露了一个浏览器端 OCR 裁切计算错误：
`pad` 已是像素值，但 v4.0 又将其作为比例参与 `cell*(1-2*pad)`，
导致单格取图宽高为负数，因此 81 个校对格全部为空。

v4.1 已改为 `cell - 2*pad`。
用用户此前的 KI-7370 截图按真实棋盘区域复现后：
- 81 格切分正常
- 主数字检测：47 个
- 预期主数字：47 个
- 小候选数字未被主数字检测器纳入
同时加入“少于17个主数字禁止宣称可解、禁止导入”的保护。

## v4.2 OCR 回退增强
- 针对“素数独”截图复测：修正单格裁切后，主数字检测为 47/47。
- 本地 Tesseract 单数字模式 psm10 为 46/47；唯一漏识别的数字 3 在 psm8/13 可正确识别。
- 因此移动端 OCR 改为 psm10 优先，空白或低置信度时自动以 psm8、psm13 复核。


## v4.3 核心修复
- 根因确认：此前默认四角是“整张截图”的四角，而不是数独棋盘四角，导致整张手机截图被压缩成 9×9 后识别。
- 新增自动棋盘定位：利用数独的 4 条主横线和 4 条主竖线自动锁定棋盘边界。
- 回归集：KI-7370 + 10专家 + 5大师 + 5极限，共 21 张截图，自动棋盘定位 21/21 成功。
- KI-7370 自动定位后，本地同流程 OCR 结果 81/81 格正确：47 个正式数字正确，34 个空格保持为空。
- 移除 sudoku.vc 专用字体模板优先策略，防止对“素数独”等其他字体产生高置信度误判。
- 所有主数字改用 Tesseract psm 10 / 8 / 13 三模式投票。
